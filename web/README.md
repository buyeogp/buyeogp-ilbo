# 화면 (web)

현장 팀장이 매일 두수를 넣고, 본사가 확인하고 확정하는 화면.
React 19 + Vite. 상태 관리 라이브러리도, 그리드 라이브러리도 쓰지 않는다.

```
web/
  index.html
  src/
    main.jsx            진입
    App.jsx             껍데기 · 돈사 탭 · 라우팅
    api.js              /api 호출 한 곳 · 날짜 도우미
    styles.css          색·글꼴·표 (디자인 토큰)
    pages/
      Login.jsx         로그인
      DailyReport.jsx   일보 입력 — 이 프로젝트의 본체
      HouseStatus.jsx   제출 현황 (본사 신호등, §5.8)
    components/
      Grid.jsx          표 그리드 · 키보드 조작 · 행별 검산
```

```bash
npm install
npm run dev      # http://localhost:5173  (/api 는 127.0.0.1:3000 으로 넘긴다)
npm run build
```

API 서버가 같이 떠 있어야 한다.

```bash
cd ../api && npm run dev
cd ../api && node src/db/dev-user.js    # 눌러 볼 계정 발급, 끝나면 --drop
```

## 그리드 라이브러리를 쓰지 않는 이유

AG Grid 를 먼저 검토했다. 쓰지 않기로 한 이유는 세 가지다.

| | 이 일보 | 그리드 라이브러리가 잘하는 일 |
|---|---|---|
| 행 수 | 가장 큰 분만사가 **44행** (11돈방 × 4축종) | 수천~수만 행 가상 스크롤 |
| 열 구성 | 종이 일보와 **똑같아야** 한다 (§3.3) | 자체 헤더·정렬·필터 UI |
| 무게 | — | 약 1MB |

44행에 가상 스크롤은 값이 없다. 반대로 「돈방 이름을 rowspan 으로 한 번만
적는다」, 「전일두수는 회색 읽기전용」, 「차이가 나면 그 칸만 붉게」 같은,
**종이와 같아 보이게 하는 것**은 남의 그리드를 설득하는 쪽이 더 오래 걸린다.
지금 그리드는 200줄이고 빌드 결과에서 차지하는 몫은 수십 KB다.

## 화면이 계산하지 않는다

| 값 | 누가 정하나 | 화면에서는 |
|---|---|---|
| 전일두수 | V2 트리거 | 회색 · 읽기전용 |
| 당일두수 | 생성열 (V1) | 회색 · 굵게 (저장 전에는 미리보기) |
| 폐사·도태 | 폐사/도태 원장 (V7) | 회색 · 읽기전용 |
| 전입·전출·내부이동·판매 | **사람** | 입력 |

당일두수는 저장 전에도 보여 줘야 해서 화면이 한 번 계산한다. 그 값이 DB
생성열과 어긋나면 저장하는 순간 숫자가 바뀌어 바로 드러난다 —
`api npm run smoke` 의 「저장 전 예상 전일두수 = 저장 후 실제 전일두수」가
그것을 매번 확인한다.

## 빈칸을 허용하지 않는다

「변동 없음」은 **0 을 쳐서** 말한다. 빈칸은 「없었다」와 「아직 안 봤다」를
구별하지 못한다. 대신 한 행을 한 번에 0 으로 채우는 키를 둔다
(<kbd>Ctrl</kbd>+<kbd>Enter</kbd>).

일보 전체를 한 번에 채우는 단추는 **만들지 않는다**. 설계문서 §8.1 이
「전날 값 전체 복사」를 금지한 것과 같은 이유다 — 한 번 누르면 일보가 사실이
아니게 된다.

## 키

| 키 | |
|---|---|
| <kbd>Tab</kbd> / <kbd>→</kbd> | 다음 칸 (줄 끝에서 다음 행) |
| <kbd>Enter</kbd> / <kbd>↓</kbd> | 같은 칸 다음 행 |
| <kbd>Ctrl</kbd>+<kbd>Enter</kbd> | 이 행 변동없음 (빈칸을 0 으로) |
| <kbd>Ctrl</kbd>+<kbd>S</kbd> | 임시저장 |

<kbd>Ctrl</kbd>+<kbd>0</kbd> 은 크롬의 배율 초기화라 쓰지 않는다.

## 경고를 묶어서 보여 준다

서버 검증(`fn_validate_report`)은 **행마다 하나씩** 준다. 빈 분만사 일보를
열면 55건이 온다. 그대로 늘어놓으면 붉은 벽이 되어 정작 고쳐야 할 표가 화면
밖으로 밀린다 — 실제로 처음 만들었을 때 그렇게 됐다.

같은 규칙은 한 줄로 묶고 어디인지만 적는다. 나머지는 표에서 색으로 보인다
(§6.4 P10 — 「오류는 위치와 색상으로」).

## 못 고치는 상태는 못 고치게 보인다

입력이 막히는 경우가 셋이다 — 아직 「일보 시작」 전, 담당 돈사가 아님,
이미 제출·확정됨. 처음에는 셋 다 **입력칸 모양 그대로** 두고 조용히 안 받았다.
치는 사람은 자기가 뭘 잘못했는지 알 길이 없다.

지금은 못 쓰는 칸을 회색 글자로 바꾸고, 표 위에 왜인지 한 줄 적는다.

| 상태 | 화면 |
|---|---|
| 미시작 · 담당 팀장 | 「아래 "일보 시작"을 누르면 입력할 수 있습니다」 + 단추 |
| 미시작 · 그 외 | 「담당 팀장이 시작해야 합니다」 |
| 담당 돈사 아님 | 「보기만 할 수 있습니다. 입력은 담당 팀장 계정에서 합니다」 |
| 제출·확정·마감 | 「고칠 수 없습니다. 고쳐야 하면 정정전표를 발행하십시오」 |

## 휴대폰

입력은 사무실 PC 에서 한다. 좁은 화면에서는 **보기 전용 카드**로 바뀌고
그 사실을 화면에 적는다. 돈사 안에서 「지금 이 방 몇 마리지」를 확인하는 용도다.

현장 입력을 휴대폰으로 옮기려면 그리드가 아니라 **다른 화면**이 필요하다
(돈방 하나씩 넘기는 단계형). 지금은 만들지 않았다.
